# Quality 0.0.6

Calibration now retains evaluation scope from Core and identifies sweep scores as
selection validation rather than an independent test. This context accompanies
active models, charts, prediction CSVs and model export/import. Imported evaluation
claims remain declared-only and cannot qualify routine predictions.

Unsupported preprocessing operations and parameters are refused explicitly. JS
fallback MSC is fitted on training rows only, replayed on validation rows, and
refitted separately for deployment. Tiny, overlapping and repeated-sample splits
are refused instead of producing resubstitution scores. Candidate failures remain
visible without discarding supported candidates; complete pipeline failures are
reported on screen. Catalog SG edge handling is explicit on both backends.

The release preserves the published 0.0.5 native PCA/T²/Q diagnostics, calibration-only
projection, physical-axis alignment, structured uncalibrated uncertainty and shared
Preflight/Domains evidence. Missing scores remain unavailable and zero is preserved.
An independent score alone cannot calibrate a heuristic prediction band.

Core remains pinned to 0.4.6 and UI to 0.1.15. Methods 1.3.10 and the paired runtime
inputs are qualified for this build. The release provenance distinguishes downloaded
public npm artifacts from web-target rebuilds of exact published source tags.

The native scientific suite and the new calibration regression suite both run
through `npm run test:science`. Additional gates cover Methods admission, shared
assessment contracts, model import, type checking, build and real Chromium journeys.
See [the scientific review](../reviews/2026-11-03-scientific-correctness.md) and
[the release integration review](../reviews/2026-11-03-release-integration.md).

Release artifacts contain the static application, the qualified runtime-input
cohort for rebuilding, SHA-256 checksums, build provenance and validation results.
